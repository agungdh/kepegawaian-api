# AGENTS.md

Panduan konvensi proyek **kepegawaian** untuk semua agent/kontributor. Aturan di bawah ini **wajib** diikuti saat membuat tabel, migration, entity, repository, maupun fitur baru.

## Ringkasan Proyek

- Java 25, Spring Boot 4.1.2, Gradle Kotlin DSL
- Spring Data JPA + Hibernate (`ddl-auto: validate`)
- PostgreSQL 18
- Flyway (`classpath:db/migration`)
- Base package: `id.my.agungdh.kepegawaian`

## Aturan Wajib Database

### 1. Primary Key Selalu `BIGINT GENERATED ALWAYS AS IDENTITY`

Semua tabel **wajib** punya primary key dengan pola berikut:

```sql
id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

- Jangan pakai `SERIAL`, `BIGSERIAL`, UUID, atau sequence manual untuk primary key.
- Jangan pakai `GENERATED BY DEFAULT`; gunakan `GENERATED ALWAYS`.
- `id` adalah **identifier internal** (untuk join, FK, dan performa). **Jangan pernah diekspos ke API/FE.**
- Di JPA:

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

### 2. Setiap Tabel Wajib Punya Kolom `uuid` (Identifier Publik)

Semua tabel **wajib** punya kolom `uuid` yang dipakai sebagai identifier publik untuk FE/API:

```sql
uuid UUID NOT NULL DEFAULT gen_random_uuid()
```

Ketentuan:

- Tipe kolom `UUID`, **bukan** `VARCHAR`/`TEXT`.
- **Tidak perlu `UNIQUE`** (sesuai keputusan proyek).
- Wajib diberi **hash index**, karena lookup selalu berbasis equality (`WHERE uuid = ?`):

```sql
CREATE INDEX idx_employees_uuid
    ON employees USING hash (uuid);
```

- `uuid` **wajib** diekspos ke FE. `id` bigint **tidak boleh** diekspos.
- UUID boleh di-generate di database (`gen_random_uuid()`, bawaan PostgreSQL 13+) dan/atau di entity lewat `UUID.randomUUID()`.

### 3. Setiap Tabel Wajib Punya 6 Kolom Audit

Tanpa terkecuali (tabel utama, tabel relasi, tabel lookup, tabel riwayat), setiap tabel harus punya:

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
created_by BIGINT,
updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_by BIGINT,
deleted_at TIMESTAMPTZ,
deleted_by BIGINT
```

Ketentuan:

- Semua kolom `*_at` **wajib** bertipe `TIMESTAMPTZ` (bukan `timestamp`, `timestamp without time zone`, atau `date`).
- Kolom `*_by` bertipe **sama dengan ID user**, yaitu `BIGINT`. Tabel `users` belum ada, jadi untuk sementara **tanpa foreign key**. Saat modul user dibuat, tambahkan FK ke `users(id)` tanpa mengubah tipe kolom.
- `created_by` dan `updated_by` boleh `NULL` selama modul user/auth belum ada. Setelah modul user tersedia, ubah menjadi `NOT NULL` lewat migration baru.
- `deleted_at` dan `deleted_by` `NULL` berarti data aktif.

### 4. Soft Delete

- **Dilarang hard delete** (`DELETE FROM ...`) untuk data bisnis.
- Hapus data = isi `deleted_at = now()` dan `deleted_by = <user id>`.
- Semua query baca wajib mengecualikan data terhapus (`deleted_at IS NULL`).
- Unique constraint wajib memakai partial index agar data terhapus tidak bentrok:

```sql
CREATE UNIQUE INDEX uq_employees_nip_active
    ON employees (nip)
    WHERE deleted_at IS NULL;
```

Contoh di entity:

```java
@SQLRestriction("deleted_at IS NULL")
```

Helper soft delete:

```java
public void softDelete(Long userId) {
    this.deletedAt = Instant.now();
    this.deletedBy = userId;
}
```

### 5. Konvensi Penamaan

- Nama tabel: **plural, snake_case** (contoh: `employees`, `attendances`, `leave_requests`).
- Nama kolom: **snake_case**.
- Primary key: `id` (internal).
- Identifier publik: `uuid`.
- Foreign key (di database): `<nama_entity>_id` (contoh: `employee_id`, `department_id`). **Tidak diekspos ke FE.**
- Foreign key publik (di DTO/API): `<nama_entity>_uuid` (contoh: `employee_uuid`, `department_uuid`). **Ini yang diekspos ke FE.**
- Index: `idx_<tabel>_<kolom>`.
- Hash index UUID: `idx_<tabel>_uuid`.
- Unique index: `uq_<tabel>_<kolom>`.
- Foreign key constraint: `fk_<tabel>_<tabel_referensi>`.

### 6. Template Migration

Semua migration disimpan di `src/main/resources/db/migration` dengan nama:

```
V<versi>__<deskripsi_snake_case>.sql
```

Contoh `V1__create_employees.sql`:

```sql
CREATE TABLE employees (
    id   BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    uuid UUID NOT NULL DEFAULT gen_random_uuid(),

    nip  VARCHAR(30)  NOT NULL,
    name VARCHAR(150) NOT NULL,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by BIGINT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by BIGINT,
    deleted_at TIMESTAMPTZ,
    deleted_by BIGINT
);

CREATE INDEX idx_employees_uuid
    ON employees USING hash (uuid);

CREATE UNIQUE INDEX uq_employees_nip_active
    ON employees (nip)
    WHERE deleted_at IS NULL;

CREATE INDEX idx_employees_deleted_at
    ON employees (deleted_at);
```

Contoh tabel anak dengan FK:

```sql
CREATE TABLE attendances (
    id           BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    uuid         UUID NOT NULL DEFAULT gen_random_uuid(),
    employee_id  BIGINT NOT NULL,

    attendance_date DATE NOT NULL,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by BIGINT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by BIGINT,
    deleted_at TIMESTAMPTZ,
    deleted_by BIGINT,

    CONSTRAINT fk_attendances_employees
        FOREIGN KEY (employee_id) REFERENCES employees (id)
);

CREATE INDEX idx_attendances_uuid
    ON attendances USING hash (uuid);

CREATE INDEX idx_attendances_employee_id
    ON attendances (employee_id);
```

> Di database FK tetap memakai `<entity>_id` bigint. Yang diekspos ke FE adalah `<entity>_uuid` yang diambil dari relasi (bukan kolom terpisah di tabel anak).

Aturan migration:

- Satu migration untuk satu perubahan logis.
- Migration yang sudah pernah dijalankan **tidak boleh diedit**; buat migration baru.
- Karena `ddl-auto: validate`, tipe kolom di entity harus persis sama dengan hasil migration.
- Jangan mengandalkan generate otomatis Hibernate untuk membuat tabel.

## Aturan JPA / Entity

### Base Entity

Semua entity bisnis wajib extends `AuditableEntity` (buat di `id.my.agungdh.kepegawaian.common.persistence`):

```java
package id.my.agungdh.kepegawaian.common.persistence;

import jakarta.persistence.Column;
import jakarta.persistence.EntityListeners;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.MappedSuperclass;
import lombok.Getter;
import lombok.Setter;
import org.springframework.data.annotation.CreatedBy;
import org.springframework.data.annotation.CreatedDate;
import org.springframework.data.annotation.LastModifiedBy;
import org.springframework.data.annotation.LastModifiedDate;
import org.springframework.data.jpa.domain.support.AuditingEntityListener;

import java.time.Instant;
import java.util.UUID;

@Getter
@Setter
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class AuditableEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "uuid", nullable = false, updatable = false)
    private UUID uuid = UUID.randomUUID();

    @CreatedDate
    @Column(name = "created_at", nullable = false, updatable = false)
    private Instant createdAt;

    @CreatedBy
    @Column(name = "created_by", updatable = false)
    private Long createdBy;

    @LastModifiedDate
    @Column(name = "updated_at", nullable = false)
    private Instant updatedAt;

    @LastModifiedBy
    @Column(name = "updated_by")
    private Long updatedBy;

    @Column(name = "deleted_at")
    private Instant deletedAt;

    @Column(name = "deleted_by")
    private Long deletedBy;

    public boolean isDeleted() {
        return deletedAt != null;
    }

    public void softDelete(Long userId) {
        this.deletedAt = Instant.now();
        this.deletedBy = userId;
    }
}
```

Entity baru cukup:

```java
@Entity
@Table(name = "employees")
@Getter
@Setter
@NoArgsConstructor
public class Employee extends AuditableEntity {
    @Column(nullable = false, length = 30)
    private String nip;

    @Column(nullable = false, length = 150)
    private String name;
}
```

### Tipe Waktu

- Gunakan `Instant` (atau `OffsetDateTime`) di Java untuk kolom `TIMESTAMPTZ`.
- **Jangan** gunakan `LocalDateTime` untuk kolom `*_at` audit.
- `updated_at` diurus oleh auditing Hibernate. Jika melakukan update lewat native query, isi `updated_at`/`updated_by` secara eksplisit.

### UUID untuk API (Wajib)

- **Jangan pernah** mengembalikan entity JPA langsung dari controller. Selalu pakai DTO.
- DTO response hanya berisi `uuid` dan `<relasi>_uuid`. **Jangan** sertakan `id` atau `<relasi>_id`.
- DTO request untuk relasi memakai `<relasi>_uuid`. Service wajib resolve UUID tersebut menjadi entity/FK `id` di database.
- Path endpoint memakai UUID, contoh `GET /api/employees/{uuid}`.
- Repository menyediakan lookup berbasis UUID:

```java
Optional<Employee> findByUuid(UUID uuid);
```

Contoh response DTO:

```java
public record EmployeeResponse(
        UUID uuid,
        String nip,
        String name,
        UUID departmentUuid
) {
}
```

Contoh request DTO:

```java
public record EmployeeRequest(
        @NotBlank String nip,
        @NotBlank String name,
        @NotNull UUID departmentUuid
) {
}
```

Contoh resolve FK di service:

```java
Department department = departmentRepository.findByUuid(request.departmentUuid())
        .filter(d -> !d.isDeleted())
        .orElseThrow(() -> new NotFoundException("Department not found"));

Employee employee = new Employee();
employee.setNip(request.nip());
employee.setName(request.name());
employee.setDepartment(department);
```

Contoh mapping ke response:

```java
new EmployeeResponse(
        employee.getUuid(),
        employee.getNip(),
        employee.getName(),
        employee.getDepartment().getUuid()
);
```

### Auditing

Aktifkan JPA auditing sekali di konfigurasi:

```java
@Configuration
@EnableJpaAuditing(auditorAwareRef = "auditorProvider")
public class JpaAuditingConfig {

    @Bean
    AuditorAware<Long> auditorProvider() {
        // Sementara kosong karena modul user/auth belum ada.
        // Ganti dengan pembacaan dari SecurityContext setelah modul user tersedia.
        return Optional::empty;
    }
}
```

## Checklist Sebelum Selesai

- [ ] Primary key `id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
- [ ] Ada kolom `uuid UUID NOT NULL DEFAULT gen_random_uuid()` dan hash index `idx_<tabel>_uuid`
- [ ] `uuid` **tidak** diberi constraint/index `UNIQUE`
- [ ] Ada 6 kolom audit: `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`, `deleted_by`
- [ ] Semua kolom `*_at` bertipe `TIMESTAMPTZ`
- [ ] Semua kolom `*_by` bertipe `BIGINT`
- [ ] Entity extends `AuditableEntity`
- [ ] DTO hanya mengekspos `uuid` dan `<relasi>_uuid` (tidak ada `id` / `<relasi>_id`)
- [ ] Request relasi memakai `<relasi>_uuid` dan di-resolve ke FK `id`
- [ ] Query/repository mengecualikan `deleted_at IS NOT NULL`
- [ ] Unique constraint memakai partial index `WHERE deleted_at IS NULL`
- [ ] Migration baru (tidak mengedit migration lama)
- [ ] Entity dan migration konsisten dengan `ddl-auto: validate`
- [ ] `./gradlew test` lulus

## Larangan

- ❌ Hard delete data bisnis
- ❌ `SERIAL` / `BIGSERIAL` / UUID sebagai PK
- ❌ Menjadikan `uuid` sebagai primary key atau memberinya `UNIQUE`
- ❌ Mengekspos `id` atau `<relasi>_id` ke API/FE
- ❌ `timestamp without time zone` untuk kolom audit
- ❌ Tabel tanpa kolom audit
- ❌ Mengedit migration yang sudah dijalankan
- ❌ Membuat tabel lewat `ddl-auto` / auto-generate Hibernate
